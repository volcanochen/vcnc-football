# 自定义集锦：数据格式与分享/跳转方案

> 需求：未登录也能在本地做集锦（每个视频一个列表）；登录后可把整份列表写进该视频的
> B 站评论区并在每次登录时读回；可以加载别人的集锦；单个片段能分享给微信好友。
>
> 实现见 `static/clips.js`（前端）、`BiliSocial.java` / `social.py`（评论区读写）、
> `share/index.html`（微信中转页）。本文只定格式与链路。

---

## 1. 三份数据，一个坐标轴

**时间坐标统一用「原始录像烧录钟」**（和 VCNC 置顶评论的 `0:04:02` 同一条轴）。
制作片段时播放器给的是流时间 `currentTime`，写入前一律 `toOrig(currentTime)` 换算；
播放时再由 `buildSegs()` 走 `toStream()` 换回流时间。这样时间码校准、前后补时怎么改，
自定义片段和官方片段始终对齐，也不会因为换一台设备/重新校准而整体漂移。

| 存储 | 键 | 内容 | 生命周期 |
|---|---|---|---|
| 本地 | `localStorage['vcnc.clips.v1']` | `{ "<bvid>": { nick, list:[clip] } }` | 常驻本机，**未登录也可用** |
| 云端 | 该视频评论区里带标记的一条（或几条）评论 | 同一份 `list` 的文本化 | 随 B 站评论，删了就没了 |
| 分享 | 一段纯文本 `VC1.…` | 1~N 个 clip | 微信里复制粘贴即可，无服务器 |

### clip 结构（内部，JSON）

```json
{ "id": "k3f9a", "s": 242, "d": 17, "u": "阿飞", "n": "进球", "t": 1762950000 }
```

| 字段 | 含义 |
|---|---|
| `id` | 本机生成的短 id，删改/去重用 |
| `s` | 起点，原始钟秒 |
| `d` | 时长，秒 |
| `u` | 用户名（未登录＝本机昵称，登录后＝B 站昵称） |
| `n` | 备注（预设标签或自填） |
| `t` | 创建时间，排序/展示用 |

## 2. B 站评论区格式

**一条评论承载一场视频的一整个列表**，形状刻意贴近 VCNC 官方置顶评论
（`时间戳 + 时长 + 备注`），只是中间多一个 `@用户名`，并用固定头标记避免被
官方集锦解析器误认：

```
【VCNC集锦v1】BV1p5xd6hEK2 @阿飞
0:04:02 17s @阿飞 进球
0:12:30 22s @阿飞 过人
0:31:08 9s @阿飞 扑救
```

- 头行前缀固定 `【VCNC集锦v1`，格式严格为 `前缀[ n/m]】BV号 @昵称`
  （`BV…` 与 `@昵称` 之间只有一个空格，**不要加 `·` 之类分隔符，否则解析不认**）；
  解析只认这个前缀，**不会把普通评论当成集锦**。
- 数据行正则：`^(\d+:\d{1,2}(?::\d{1,2})?)\s+(\d+(?:\.\d+)?)s\s+@(\S+)\s*(.*)$`；
  用户名在落盘前已压掉所有空白，不会把备注切坏。
- 单评论上限 900 字符（B 站硬上限 1000，`clipsPublish()` 也会拒收 >1000 字），超出自动分片，
  头行变成 `【VCNC集锦v1 1/2】…`；按 `片序` 拼接，最多 3 片，
  放不下的片段留在本地并在工作室提示（`packedDropped()`）。
- **发布＝追加，不删旧评论**（2026-11-13 起，用户明确要求）：两种模式——
  - **增量发布**：剔除掉之前发过的片段（本地发布记录 `vcnc.clips.pub.v1` 按
    起点秒记键 ∪ 评论区自己所有分片解析出的起点），只把没发过的新片段
    作为一条新评论发出去；没有新增时提示。已发内容记录在 `pubSet()`，
    成功后 `markPublished()` 落盘；
  - **全量发布**：整份列表直接发成一条新评论（超长自动分片，≤3 片）。
  - 因为不删旧评论，同一个人在评论区可能有多条集锦评论；读取端把
    「自己 mid 的所有分片组」合并去重（按起点秒）后统一作为 `cloud.mineAll`
    展示与比对。
- **删除即丢失**：登录时读取评论区，自己发的集锦评论若已不存在，云端来源的片段
  从合并列表里撤掉并提示；**本地列表不受影响**（这正是需求 1 的兜底价值）。
- 别人的集锦：同一批评论里按 `mid` 分组，走「载入」按钮选择性合并，
  默认不自动灌进播放列表。

写接口（两端同语义，均要求登录态 + 同源 POST 校验）：

| 端点 | 作用 |
|---|---|
| `GET /api/replies?aid=…&pages=3&ps=20` | 返回 `{ok,count,matched,replies}`；`replies[]` 含 `rpid / mid / user / text / time`。`pages` 两端默认 5、上限 15，前端只读 3 页以避开 `-412` 风控 |
| `POST /api/clips/publish` | `oid + message + bvid` → `/x/v2/reply/add` |
| `POST /api/clips/delete` | `oid + rpid + bvid` → `/x/v2/reply/del`（按 `rpid` 逐条删，只删自己带标记的） |

读回遇到 `-412 request was banned` 或空列表时不重试轰炸，`clips.js` 用 `cloud.nextAt`
做 30 秒退避并在工作室状态栏提示「稍后自动重试」。

B 站侧关键错误码已在两端映射成中文：`-101` 登录过期、`-111` csrf、`-509` 太频繁、
`12015` 需验证码、`12051` 重复评论、`12025` 超长、`12035` 被 UP 拉黑。

## 3. 分享码（微信里能活下来的那一层）

```
VC1.<base64url(UTF8(JSON))>.<crc8hex>
```

```json
{"v":1,"b":"BV1p5xd6hEK2","c":[{"s":242,"d":17,"u":"阿飞","n":"进球"}],"t":1762950000}
```

- `base64url` 用 `-_` 替代 `+/`、去掉 `=`，**可以直接放进 URL fragment 和微信文本**。
- `crc8` 只是防手抄漏字/传输截断，不是签名；导入时校验失败直接拒绝。
- `c` 是数组：既能分享单个片段，也能分享整场列表。
- 纯文本、无后端、无短链服务，微信怎么转都不会失效。
- 单片段约 130~170 字符；整场 30 段约 2~3 KB。**码长 >900 字符时分享文本不再附链接**
  （微信会截断长 URL），只留纯导入码；短码才会同时给 H5 链接。

## 4. 微信里怎么跳回 App（重点）

**结论：微信内置浏览器会拦自定义 scheme，个人开发者拿不到「点链接直接开 App」的
一键体验。** 官方唯一路径 `wx-open-launch-app` 需要认证服务号（企业主体、年审）+
微信开放平台移动应用（登记包名与签名）+ JS 接口安全域名 + App 集成微信 OpenSDK，
对一个免费小工具不划算。所以做成**三层降级**，第一层 100% 可用：

### A. 复制导入码（默认，零成本，微信拦不住）

分享出去的文本同时含「链接」和「导入码」：

```
【VCNC足球 · 自定义集锦】「进球」0:04:02 +17s · BV1p5xd6hEK2 · @阿飞
查看：https://volcanochen.github.io/vcnc-football/share/#d=VC1.eyJ2Ijox…
—— 微信里若打不开 App，复制下面这串，打开 VCNC足球 →「＋制作」→「从剪贴板导入」——
VC1.eyJ2Ijox…
```

对方复制 → 打开 App → 集锦浮窗工具行点「＋制作」→ 面板里点「从剪贴板导入」→
`getClipboardText()` JS 桥自动读剪贴板（`extractCode()` 从整段文本里挑出 `VC1.…`）→
校验 crc → 跳到对应视频并合并片段。**不依赖任何服务器、域名、微信配置**。
（2026-11-13 起工具行改为 `＋制作 / 自定义`，独立的「⇧导入」按钮与面板里
重复的「导入集锦」按钮都已删除，导入统一走这一个入口和深链自动导入。）

### B. H5 中转页（半自动，`share/index.html`）

- 地址 `https://<host>/share/#d=<code>`，数据全在 **fragment**（`#` 后面不发往服务器，
  服务器日志里看不到集锦内容）。
- 页面解码后展示片段信息，按钮顺序：
  1. 「打开 VCNC足球」→ 先试 `vcncfootball://import?d=<code>`；
  2. `visibilitychange` + 1.6s 定时器判断没唤起 → 显示「微信内不能直接打开，
     请点右上角 · 在浏览器打开」，并给出 `intent://` 版链接（Android 系统浏览器可用）；
  3. 仍失败 → 「复制导入码」+「下载 App」两个兜底。
- 页面里预留 `wx-open-launch-app` 的接入位（`WX_APPID` 配置 + `extinfo`），
  将来真有认证服务号/开放平台账号，填上 appid 就能升级成一键跳转，页面其余逻辑不用改。

### C. 官方一键 / App Links（可选增强，本文档给出接法）

| 方案 | 前置条件 | 微信内表现 |
|---|---|---|
| `wx-open-launch-app` 开放标签 | 认证服务号 + 开放平台移动应用（AppID、包名、签名 MD5 一致）+ JS 安全域名 + Android 集成 OpenSDK | 唯一官方可点开；`extinfo` 直接带 `VC1.…`，App 在 `ShowMessageFromWX.Req` 里取 |
| Android App Links | 自己可控的 HTTPS 域名 + `/.well-known/assetlinks.json` 放签名 SHA256 + manifest `android:autoVerify="true"` | 系统浏览器/扫码能直接进 App；微信内仍常被拦，只作增强 |
| URL Scheme `vcncfootball://import` | 只需 manifest intent-filter（**本版已加**） | 系统浏览器、短信、二维码可用；微信内多数被拦 |

> 本版已落地：A（剪贴板桥 + 导入面板）、B（静态中转页 + scheme/intent 深链）、
> C 的 scheme 部分与接入文档。开放标签/App Links 只留配置位，等有域名和资质再开。

## 5. 颜色与来源

同一个浮窗列表里混排，靠**整行文字换色**（序号 / 时间 / 备注）+ 左侧色条 + 极淡底色区分；
官方片段保持默认白 / 灰，选中态的蓝底优先，不会被来源色盖掉：

| 来源 | 标记 | 颜色 |
|---|---|---|
| VCNC 官方置顶评论 | `src='vcnc'` | 原样（白/蓝高亮） |
| 我·本机自定义 | `src='mine'` | 青绿 |
| 我·评论区读回 | `src='cloud'` | 蓝紫 |
| 别人·已载入 | `src='other'` | 橙黄 |

`segs[i]` 带上 `src / user / cid`，`renderSegFloat()` 据此加 class；
删除、编辑、分享只对 `mine` 开放，避免误改别人或云端的数据。

**「自定义」筛选**：浮窗工具行第二个按钮（`VCNCClips.setMineOnly()`）切换「只看自己创建的片段」。
它只过滤 `#sfBody` 里渲染的行，**播放序列 `segs` 与行上的 `data-i` 原始索引都不变**，
所以点行跳段不会错位；`#sfCount` 显示 `自定义段数/总段数`。再点一次恢复全部。
筛选开启时**「下一段」也只在自定义片段里走**：`ClipPlayer.nextIdx()` 从当前段往后
只接受 `src==='mine'` 的段（连播推进与段末硬切共用这条路径），后面的全是官方段就
播完停住；切换筛选时立刻 `prepareNext()` 重备备用 deck，避免按旧序列预热错位。

**行内编辑**：工作室「本场片段」列表里点行上的文字（时间 / 备注 / 昵称）展开编辑态，
可改**起点**（`mm:ss` 或秒数）、**时长**（秒）、**备注**；保存后 `updateLocal()`
按新起点重排本地列表并重建播放序列，非法值拒绝保存。

**浮窗宽度**：`.segfloat` 106px；≤380px 的低分辨率直屏 media query 强制 94px 并隐藏
序号列，字号一律不动（≥12px 红线），靠收紧 padding / 序号列与备注 ellipsis 保证可读。

**面板与播放画面同层**：制作面板（`#clipsStudio`）只属于播放页——切到比赛列表 /
设置页（`body[data-page]` 被同步切换）、或登录弹层打开（`social.js` 同步 `body.soc-modal-open`）
时整体退场（`opacity:0 + pointer-events:none`），绝不压在这些全屏界面上面；
切回播放页 / 关掉弹层即恢复打开时的原状。
